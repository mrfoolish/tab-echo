# 批量直接移除与回收站确认交互设计

## 目标

在完整页和弹窗页为“已关闭标签页”提供批量直接移除能力，并用统一的页面内二阶段确认替代回收站当前连续两次浏览器原生确认框。所有按钮和提示必须清楚区分“移至回收站”和“直接移除”。

## 操作范围

### 已关闭标签页

- 无搜索词时，批量直接移除当前浏览上下文中的全部已关闭记录。
- 有搜索词时，批量直接移除当前搜索条件命中的全部关闭记录。
- 完整页的分页和弹窗的展示上限都不限制操作范围。按钮数量使用后台返回的全部结果数，而不是当前页或弹窗中可见的数量。
- 搜索命中 Group 中任意标签页时，批量操作作用于整条关闭记录，与现有搜索结果和“移至回收站”的完整事件语义保持一致。
- 常规与无痕上下文相互隔离。

### 回收站

- “清空回收站”仍清空当前浏览上下文中的全部回收站记录，不受搜索词和分页影响。
- 单条“直接移除”维持现有规则，不要求确认。

## 页面内二阶段确认

第一次点击危险批量按钮只展开当前页面内的确认面板，不修改数据。面板包含操作对象、准确记录数、标签页数，以及“无法恢复”的说明。用户必须点击面板内的确认按钮才执行，也可以取消。

### 完整页已关闭标签页

- 无搜索词：入口显示“全部移除”；确认文案为“将直接移除全部 X 条关闭记录（Y 个标签页），无法恢复”。
- 有搜索词：入口显示“移除 X 条搜索结果”；确认文案明确只处理当前搜索条件的全部结果。
- 操作为“确认移除”“取消”。

### 弹窗页已关闭标签页

- 与完整页使用相同范围和计数规则。
- 确认面板固定显示在搜索与摘要区域下方、记录列表上方，保证在弹窗有限高度内可见，不遮挡内容。
- 打开确认面板时不自动关闭弹窗，不使用 `window.confirm()`。
- 确认按钮执行期间禁用相关批量和单条操作，完成后刷新结果并显示显著成功提示。

### 完整页回收站

- 点击“清空回收站”后展开同位置的确认面板，显示“将清空回收站中的 X 条记录（Y 个标签页），无法恢复”。
- 操作为“确认清空”“取消”。
- 移除现有两次 `window.confirm()`；页面内的第一次入口点击和第二次明确确认仍构成二阶段确认。

## 状态与失效规则

- 搜索词、页面视图或已加载结果发生变化时，立即关闭旧确认面板，避免确认过期范围。
- 确认请求不依赖前端传入的全部 ID：批量搜索移除发送查询条件，由后台在执行时重新匹配当前数据；无搜索词按全部记录执行。
- 确认面板展示的是预览计数。若预览后数据变化，后台按相同范围处理当前数据，成功提示使用实际移除数量。
- 请求失败时保留当前列表，关闭执行中状态并显示错误；不得显示成功提示。
- 当匹配结果为零时禁用入口并关闭确认面板。

## 后台协议

- 扩展历史直接移除协议，使其支持以下二选一参数：
  - `eventIds`：单条或显式选中记录。
  - `all: true, query`：按当前搜索条件移除全部结果；空查询表示全部记录。
- 同时传入 `eventIds` 与 `all`、未传有效选择，均返回无副作用的无效请求错误。
- 回收站继续使用现有 `empty-trash` 协议。
- 后台响应包含实际移除的记录数；批量确认面板所需标签页数来自当前已加载查询结果或回收站统计。

## 视觉与可访问性

- 确认面板使用克制的危险色边框和浅色背景，不使用大面积高饱和红色。
- 确认按钮使用危险动作样式；取消按钮使用中性样式。
- 面板使用 `role="alert"`，展开后将焦点移至确认标题或确认按钮；取消和成功后将焦点合理归还入口。
- `Escape` 可关闭当前确认面板。
- 中文使用“全部移除”“移除 X 条搜索结果”“确认移除”“确认清空”；英文使用 “Remove all”“Remove X results”“Confirm removal”“Confirm emptying”。

## 测试与验收

- 完整页无搜索和有搜索两种批量范围正确，且跨分页处理全部结果。
- 弹窗展示上限为 10、100 或 200 时，批量操作仍处理后台全部搜索结果。
- 搜索命中 Group 子标签时，整条记录被移除。
- 第一次点击不修改数据，确认后才执行；取消、`Escape` 和搜索变化均不会删除数据。
- 回收站清空不再调用 `window.confirm()`，仅页面内确认后执行。
- 单条直接移除不新增确认。
- 操作遵守常规/无痕隔离，失败时无错误成功提示，成功反馈使用实际移除数量。
- 中英文长文案、键盘操作、窄弹窗以及浅色/深色主题均可读。
