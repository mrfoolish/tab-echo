# 域名排除保存与已有记录处理设计

## 目标

将“清理已有匹配记录”合并进保存设置流程。用户新增排除域名时，在同一处明确决定是否保留或直接移除已有匹配记录，不再依赖独立按钮。

## 交互流程

1. 用户编辑设置并点击“保存设置”。
2. 系统比较已保存规则和表单规则，只取本次新增的域名。
3. 系统同时预览以下四类保存影响：超过最大记录数的关闭记录、超过历史保留天数的关闭记录、超过回收站保留天数的回收站记录，以及新增域名在当前浏览上下文中命中的已有记录。
4. 所有影响均不存在时直接保存。
5. 任一影响存在时都不直接保存，而是在同一个页面内面板中按原因分别展示记录数和标签页数，并展示去重后的合计影响。条数或期限清理是应用新保留策略的必然结果，确认保存后无法单独跳过。
6. 新增域名命中已有数据时，页面内提示命中记录数和标签页数，并说明新规则默认只影响以后关闭的标签页。用户可选择：
   - “仅保存规则”：保存全部设置，保留已有匹配数据。
   - “保存并移除”：保存全部设置，然后直接移除仅由本次新增域名命中的已有标签页；不进入回收站，无法恢复。
   - “取消”：不保存设置，也不移除数据。
7. 按影响类型展示操作：
   - 仅有条数或期限影响：“确认并保存”“取消”。
   - 仅有新增域名影响：“仅保存规则”“保存并移除”“取消”。
   - 两类影响同时存在：“保存并按保留规则清理”“保存并移除全部预览数据”“取消”。前一个选项保留未被条数或期限规则淘汰的域名匹配旧数据，后一个选项还会移除新增域名命中的其余旧数据。
8. 影响确认面板出现后，隐藏表单底部原始“保存设置”按钮，确认面板成为唯一操作入口。取消确认、修改任意设置、完成保存或重新加载设置后，恢复“保存设置”按钮。

## 匹配与数据边界

- `example.com` 匹配该 hostname 及其子域名。
- 仅计算新规则相对已保存规则增加的域名；原有规则不会因再次保存而重复触发询问。
- 已从规则中删除后又重新添加的域名属于本次新增规则。
- 只处理当前浏览上下文。常规窗口和无痕窗口数据相互隔离，需要分别保存和处理。
- 关闭组仅移除命中的标签页，未命中的标签页继续保留。
- 同一记录可能同时命中多个原因。界面按原因展示影响，同时用记录标识和标签页标识对最终合计去重，避免让用户误以为会重复删除。
- 预览到确认之间若数据发生变化，后台按相同新增域名重新计算并执行；完成提示使用实际移除数量。

## 界面调整

- 删除设置页独立的“移除已有匹配记录”按钮及其独立确认面板。
- 复用保存设置的页面内影响面板，分别展示“记录数上限”“历史保留期限”“回收站保留期限”“新增排除域名”的影响与去重合计。
- 操作按钮根据上述三种影响组合动态展示，按钮文案明确实际清理范围。
- 提示使用“直接移除”“无法恢复”，避免与移至回收站混淆。

## 后台协议

- 保存预览请求携带完整设置草稿。后台根据当前已保存规则计算新增域名，并返回新增域名及其命中统计。
- 保存请求保持补丁语义。选择“保存并移除”时，请求同时明确携带本次预览得到的新增域名；后台仅允许清理仍属于新设置、且相对旧设置为新增的规则，避免清理超出用户确认范围的数据。
- 保存和匹配清理在同一浏览上下文的串行更新中完成，避免设置已保存但清理状态不明确。

## 错误处理

- 预览失败：不保存，保留表单内容并显示通用错误。
- 保存或清理失败：显示失败，不宣称成功；持久层继续遵循现有原子写入和重试约束。
- 没有新增域名或新增域名未命中：不显示域名清理选项。

## 验证

- 新增域名无历史命中时直接保存。
- 新增域名有命中时出现三项选择，并显示准确记录数和标签页数。
- “仅保存规则”保留已有匹配数据，但未来捕获生效。
- “保存并移除”只清理本次新增域名命中的标签页。
- 降低记录数、历史保留天数或回收站保留天数并产生清理影响时，保存前分别显示原因、记录数和标签页数。
- 条数、期限和域名影响重叠时，合计数字去重，两个保存选项准确区分必需的保留策略清理和可选的域名旧数据清理。
- 只修改已有规则、删除规则或修改其他设置时不出现域名清理询问。
- Group 部分命中、常规/无痕隔离、并发数据变化和保存策略同时产生清理影响时行为符合上述规则。
